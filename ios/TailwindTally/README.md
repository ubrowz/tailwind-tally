# Tailwind Tally (iOS)

A thin native shell around the real web app at
[ubrowz.github.io/tailwind-tally](https://ubrowz.github.io/tailwind-tally/) -
same map, charts, Strava import and backend, unchanged. The one thing this
app adds: it's a registered handler for `.gpx` files, so a route shared from
Strava's app, Mail, AirDrop or Files can be opened straight into the running
page via the Share Sheet, without going through the in-browser file picker.

## Opening the project

The `.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
from `project.yml` - it's checked in, so you can just open
`TailwindTally.xcodeproj` in Xcode directly. If you change `project.yml`
(or add/remove source files) regenerate it:

```
brew install xcodegen   # once
cd ios/TailwindTally
xcodegen generate
```

## Running it

1. Open `TailwindTally.xcodeproj` in Xcode.
2. Select your own Apple ID as the signing team (Signing & Capabilities tab)
   if running on a physical device - the simulator needs no signing at all.
3. Pick a simulator or your device as the run destination, and hit Run.

No API keys or secrets live in this project - it's a pure web-view shell
pointed at the public site, which itself calls the existing Render backend
for map tiles and Strava.

## Project layout

- `Sources/` - the three Swift files: app entry point, the `WKWebView`
  wrapper, and the coordinator that owns navigation state and the
  GPX-file hand-off.
- `Resources/Assets.xcassets` - app icon (rasterized from `favicon.svg`,
  square/full-bleed so iOS applies its own corner mask) and two colors
  (accent, launch background) matching the web app's own tokens.
- `Resources/Info.plist` - generated by XcodeGen from `project.yml`; not
  meant to be hand-edited directly (edit `project.yml`'s `info.properties`
  instead, then regenerate).
